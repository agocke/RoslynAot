# Differential harness corpus

One directory per rule ID, one directory per case beneath it:

```
corpus/<RuleId>/<CaseName>/*.cs
corpus/<RuleId>/<CaseName>/case.json   (optional)
```

Every case is compiled twice with an identical argument vector - once by
the SDK's managed `csc.dll` with the NetAnalyzers assemblies, once by
`csc-aot` with the native analyzer module - and the two diagnostic sets
are diffed. See `tools/RoslynAot.DifferentialHarness/README.md`.

`case.json` fields:

| Field | Default | Meaning |
|---|---|---|
| `description` | - | free text, for readers only |
| `rules` | `[<containing directory name>]` | which rule IDs an `Initialize`-time failure or a compiler crash in this case is attributed to. An explicit `[]` means "no rule", used by `Baseline/Empty`. |
| `extraCompilerArguments` | `[]` | appended after the shared vector, so a repeated switch such as `/target:` overrides the harness default |

The burn-down aggregates per rule ID across the *whole* corpus, not per
directory, so a case that happens to trigger several rules counts for all
of them. The directory name is documentation plus the failure-attribution
default - it is not a filter.

## Every rule ID in the module is forced to `warning`

Most CA rules default to a severity for which Roslyn skips analyzer
execution entirely; without forcing, only 5 of the module's analyzer
instances ever call `Initialize`. Cases therefore see all in-scope
analyzers running, and a case written for one rule routinely surfaces
failures belonging to others. That is intended - it is how the burn-down
finds failures faster than one case per rule would.

## Rules with no case

Four of the module's 37 rule IDs have no corpus case. Each was attempted
and measured, not assumed:

| Rule | Why there is no case |
|---|---|
| CA1824 | Needs a strongly-typed resource designer that the analyzer recognizes. Neither the `.Designer.cs` designer shape, a `[GeneratedCode("System.Resources.Tools.StronglyTypedResourceBuilder", ...)]` class, nor `/resource:` embedding made it fire from a source-only compilation. |
| CA2266 | Applies to file-based programs (`dotnet run app.cs`), which the harness's `/target:library` raw-`csc` invocation cannot produce. |
| CA2356 | Needs ASP.NET web-serialization types that are not in the `Microsoft.NETCore.App` reference pack. |
| CA2362 | The auto-generated variant of CA2352. Every way of marking the type generated that Roslyn recognizes - `.g.cs`, `.Designer.cs`, an `<auto-generated/>` header, `[GeneratedCode]` including the `TypedDataSetGenerator` tool name - still produced CA2352, so the gate is something the harness does not yet drive. Triggering it likely needs per-file `generated_code = true` in the generated globalconfig, which would require the harness to emit path-scoped sections. |

Three of the four stay `NotExercised` in the baseline. CA2362 does not:
`CA2352/Basic` makes its analyzer throw, and an `Initialize`-time failure
is attributed to every rule the analyzer declares, so CA2362 carries a
named failure without a case of its own.

`NotExercised` is deliberately not a pass. If one of these becomes
reachable, add the case and the baseline will report the improvement as
`Stale` rather than silently absorbing it.
